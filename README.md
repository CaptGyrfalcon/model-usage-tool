# AI 用量挂件（Cursor + Codex）

> **非官方 / Unofficial.** 本项目与 Cursor、Anysphere、OpenAI 均无隶属关系，也不是它们的官方产品。程序会读取本机 Cursor 登录态并调用未公开文档的账单接口，同时解析本机 Codex 会话文件。接口随时可能失效；使用本工具可能违反相关服务条款，账号存在被限制的风险。请自行判断后再使用。
>
> MIT licensed Windows widget. Not affiliated with Cursor or OpenAI. It reads local session tokens and undocumented billing APIs. Use at your own risk.
>
> **AI 辅助开发。** 本项目绝大部分代码由 AI agent 生成或辅助完成，并经人工审阅与调整。

一个常驻 Windows 通知区域的 Cursor / Codex 用量小工具。窗口不会占用任务栏位置，点右上角 `×` 只会隐藏；单击通知区域三柱图标可再次显示，右键图标可完全退出。

## 系统要求

- Windows 10 / 11 x64（目前不支持 macOS / Linux）
- [Node.js 22](https://nodejs.org/) 或更高（`node:sqlite`）
- 本机已登录 [Cursor](https://cursor.com)；Codex 用量需要本机有过 Codex 会话

## 启动

双击 `start-widget.bat` 或 `启动挂件.bat`，或在终端运行：

```bash
npm install
npm start
```

请先在 Cursor 中保持登录。Codex 只要在本机使用过即可自动发现。

## 隐私与数据

- **Cursor**：读取本机 `state.vscdb` 中的登录态，调用账单相关接口。刷新后的 access token 可能写入 `%APPDATA%\cursor-usage-widget\session.json`。
- **Codex**：解析 `.codex/sessions` 与 `.codex/archived_sessions` 中的 token 计数、模型、effort 与额度窗口；不读取或保存对话正文。
- **本地历史**：事件去重后写入 `%APPDATA%\cursor-usage-widget\usage-history.sqlite`，不会主动删除。
- **网络**：仅请求 Cursor / OpenAI 的官方接口与价目表，不会把用量上传到其它服务器。
- 界面可开隐私模式，只把邮箱显示成 `****`，套餐名称仍会显示。删除 `%APPDATA%\cursor-usage-widget` 即可清除本应用保存的数据。

漏洞报告方式见 [SECURITY.md](SECURITY.md)。请勿在 Issue 里粘贴 token 或账单截图。

## 数据来源

- **Cursor**：读取本机 Cursor 登录态并调用账单页使用的接口，获得当前额度、逐模型事件、Token 与实际计费金额。
- **Codex**：解析本机 `.codex/sessions` 和 `.codex/archived_sessions` 中的 `token_count`、模型、effort 与额度窗口元数据；若会话记录含服务端响应 `service_tier` 则优先持久化，否则回退到 `logs_2.sqlite` / 本地会话设置中的请求 tier。不读取或保存对话正文。
- **官方价目表**：OpenAI API 与 Cursor 模型价格每天最多自动检查一次，也可点顶栏 `$` 手动更新。
- **本地历史库**：两边的事件都会规范化、去重后写入 `%APPDATA%\cursor-usage-widget\usage-history.sqlite`。历史事件不主动清理，远端以后缩短历史窗口也不会删除已采集的数据。

Codex 会优先采用服务端实际响应的 `service_tier`，本机当前版本未稳定落盘响应值时，使用 `priority`（Fast 请求）或 `default`（普通请求）的本地请求证据。旧版本没有该字段的事件继续显示“速度未知”，不会猜测。为了让趋势、模型汇总和套餐额度反推使用同一口径，Codex 美元等效费用采用下方用户假设价格；四个指定模型的 Fast 为 2.5×，未知按 non-fast；Cursor 价格不变。

Cursor 总览将 Cursor Grok 4.6、Grok 4.5、Composer 2.5 归入 Cursor Models 池，第三方模型归入 Other Models 池；两个池分别累计 API 等效用量并按各自已用百分比反推池总额，Other Models 同时保留 Cursor API 返回的官方套餐美元额度。

## 功能

- 任务栏额度条：原生 `WS_CHILD` 控件直接嵌入 Explorer 任务栏，随任务栏一起隐藏、显示和移动。背景透明，透出任务栏本身的材质；采用 Segoe UI、圆角细进度条和轻微悬停底色，跟随 Windows 深浅色与高对比度模式。三行分别显示 Cursor 模型、三方模型和 Codex 剩余量；右侧固定列显示剩余百分比和池内剩余美元（`余$1145.14`），进度条长度不随文字伸缩。每条进度条下方有黄色小三角，标出周期内匀速使用时当前应剩余的位置，便于平摊额度。Codex 周池与明确存在的 5h 窗口分开显示，缺失或过期数据为 `—`。双击打开小程序窗口，右键打开操作菜单；单击不打开窗口。悬停查看额度、匀速参考与采样时间。多显示器默认也在副屏横向任务栏显示，托盘菜单和应用设置可单独关闭副屏；关闭额度条本身会一并收起。自动检测任务栏应用按钮的空位，空间不足时隐藏，避免遮挡；支持 DPI 变化与 Explorer 重建后的重新挂载。

- 总览首屏展示各额度池剩余百分比，点击可跳转到对应详情；统一深色卡片、单行导航和清晰的键盘焦点
- 同步详情区分 Cursor / Codex 已同步、缓存和暂不可用，失败时保留历史，并提供加载、失败与导出结果提示
- 设置中支持开机启动、任务栏额度条、副屏任务栏和减少动态效果；默认跟随系统，隐藏窗口暂停绘制，水位过渡按实际帧间隔推进
- 请求明细支持按模型 / effort 搜索和完整 CSV / JSON 导出；导出遵循当前来源与搜索条件，没有 8,000 条上限，使用一致的数据库快照，失败时保留已有目标文件；CSV 防止文本字段被当作公式执行
- Cursor 模型 / 其他模型额度池、已用与套餐包含美元额度，以及 Codex 当前额度窗口
- Cursor 与 Codex 的美元等效费用；Codex 周额度按 Pro5x $500 / Plus $100 的用户假设显示，其他窗口保留区间估算
- Cursor + Codex 今日总 Token、最近调用和本地历史数量
- 默认每 30 秒刷新，可选 15 秒、30 秒、45 秒、1 分钟或 2 分钟
- 首次扫描本地现有 Codex 历史，此后只读取新增日志片段
- 模型用量三档统计及数据源切换：
  - **笼统**：只区分基础模型，合并 Fast 与 thinking effort
  - **速度**：区分标准 / Fast，合并 thinking effort
  - **精确**：标准 / Fast 和每一种 thinking effort 都分别统计
- 模型统计范围下拉菜单：全部历史、近 6 / 3 / 1 个月、近 14 / 7 / 1 天、近 12 / 6 / 1 小时；全部、Cursor、Codex 始终使用同一滚动时间范围
- 模型明细可切换文字 / 环状图，沿用来源、统计范围和精度；环状图支持总 Token、有效 Token、美元等效占比，Codex 速度未知仅在环状图中合入非 Fast，保留原始速度证据及费用
- 额度水位叠加匀速参考虚线：完整参考从周期初 100% 到周期末 0%，绘制时仅截取现有横轴范围，不为参考线延长图表；悬停采样点可比较实际与参考水位。优先使用已记录的周期起点，旧历史缺少起点时会标明推算，缺少周期结束时间时不画参考线
- 持久化新增消耗柱状图：日档按小时，周档按最近 7 天，月档按最近 30 天
- 趋势来源可切换全部 / Cursor / Codex，默认显示总 Token（含缓存），也可切换有效 Token 与美元等效费用
- 柱状图可开启输入 / 缓存输入 / 输出三色堆叠，也可同时叠 Fast / 非 Fast 比例（速度未知计入非 Fast）；Token 和美元费用视图都支持
- 每条事件的输入、缓存、输出费用和价目表版本在首次入库时锁定，之后模型降价不会改写历史成本
- 全屏仪表盘：点击标题栏 `⛶`、通知区域菜单或按 `F11` 进入，按 `Esc` / `F11` 退出；全屏会放大字体、并排展示额度池、展开模型 Token 构成并使用宽屏趋势图
- 极简额度球：Cursor 百分比显示两位小数；额度模式按蓝、绿、黄、橙、红渐变填充，速度模式用绿色 / 泛光橙色区分普通与 Fast 消耗；用量池同时展示 Cursor 模型池、Cursor 三方模型池和 Codex 月度池。容器体积与美元等效容量成正比，文字信息均位于池体下方；拖动时液面会倾斜、回摆并激起浪花，刷新时按新增消耗播放排水和金额提示；右侧显示各额度窗口的重置时间。
- Codex 月度池：按本地自然月计算，包含所有与本月相交的完整周周期（跨月周不按天折算）。总容量 = 周周期数 × 当前推算的周容量 − 月初跨月周在上个月已消耗的额度；该笔消耗同时从本月已用量中移除，避免重复扣减。月初记录不足时只扣已知消耗，并在悬停提示中标明扣减可能不足；未来周期按当前周重置时间每 7 天外推，假设套餐和容量不变。青色表示当前可用，蓝色表示等待重置；完整服务端额度信息明确无 5h 窗口时，本周剩余全为青色，也不显示虚构的 5h 倒计时。部分响应缺字段或只有 Pro 等套餐名称不能证明没有 5h 限制。紫色为过期未用估算，灰色为“历史记录不足”，两者相邻放在液体最上方，均不计入待用额度。历史已用量优先采用服务端快照并补加之后的已记录消耗；没有快照时使用已计价的本机记录，可能缺少其他设备或未记录用量。缺少历史依据或存在未计价请求时保留灰色，避免误算成过期未用。池底仅显示名称、主要比例和总容量，悬停总容量查看解释及历史明细。缺少有效周重置时间或周容量时保留原周/5h 联合池。
- 隐私模式：只把邮箱显示成 `****`，套餐名称正常显示；支持全局快捷键切换
- Codex 当前可用的青色液体固定在池底，独立池和总池一致；灰色仅保留历史中未能确认的余额，已知消费即使与未计价记录混在同一周也照常扣除。悬停总容量可查看该周已知消费和未计价记录数量。
- 普通/迷你窗口固定置顶并保留任务栏图标；极简额度球固定置顶但隐藏任务栏图标
- 自动识别 2K/4K 显示器并同步放大非全屏窗口与字体，移到不同 DPI 的屏幕时会重新适配
- 迷你模式、极简额度球、透明度、开机启动

## 任务栏原生宿主

首次开启任务栏额度条时，会调用系统自带的 .NET Framework 4.x C# 编译器，将 `src/taskbar-native.cs` 与事件监听器编译到 `%APPDATA%\cursor-usage-widget\native`；后续按源码内容哈希复用。无需管理员权限、第三方任务栏补丁或 DLL 注入。Electron 仅通过本地管道发送额度行数据，原生进程负责绘制；关闭该功能或退出主程序会销毁子控件并退出原生进程。

这是依赖 Explorer 窗口结构的兼容实现，并非 Windows 官方任务栏扩展接口。当前支持主屏及可选副屏横向任务栏；不会挤压或修改系统按钮布局，空位不足、UI Automation 布局暂不可读时会隐藏。Windows 更新改变任务栏内部结构后可能需要适配。

原生验证与深浅色绘制样张：

```bash
npm run test:taskbar-native
```

样张输出到 `out/native/taskbar-themes.png`。

# Codex 额度区间估算

Codex 采样使用独立来源标识保存：会话 ID、原始记录行号及内容指纹，或 HTTP 日志行 ID；相同时间戳不会互相覆盖。每条记录保留来源路径与质量标记。同一会话同一时间戳下出现不同用量内容，或采样时间落在对应周期外时，保留原记录但不用于估算和趋势。显示用的合并快照不再写回历史，各窗口保留自己的采样时间。旧 `quota_samples` 表保留作为历史存档；启用新采样后，Codex 估算读取 `codex_quota_observations` 中质量有效的原始记录。

恢复工具为 `scripts/recover-codex-quota-samples.cjs --database <目标数据库> --backup <事先备份>`。恢复前退出挂件，使用 SQLite 一致性备份并在副本上验证。工具从本机会话文件和现存 HTTP 日志重建采样，不修改请求用量记录、不删除旧采样；原始日志中缺失的真实时间不会被编造。

Fast 状态未知的请求统一按 non-fast（普通模式）计价，已有记录的计价上下界也收敛到普通模式价格。原始 Fast 状态证据仍保留为未知，已确认的 Fast 请求继续按 Fast 计价。

## Codex 假设计价与验证（2026-09-18）

这是用户指定的工作假设，不是官方套餐美元余额或账单：

| 模型 | 输入 / 百万 token | 缓存输入 | 缓存写入 | 输出 |
|---|---:|---:|---:|---:|
| Sol | $4 | $0.4 | $5 | $20 |
| Luna | $1/3 | $1/30 | $5/12 | $2 |
| Terra | $2 | $0.2 | $2.5 | $12 |
| Astra | $15 | $1.5 | $18.75 | $75 |

上述价格适用于全部上下文长度；明确 Fast 乘2.5，未知档位按普通并保留原始证据。官方价格刷新不会覆盖 Codex 假设；Cursor 继续使用自己的官方价格。

Auto-review 每个完整审查 turn 收取 $0.01。通过 session ID + turn ID 去重，在 task_complete 时写入独立计费事件；同一 turn 的多条 token_count 不重复收费。未能识别完整 turn 的旧 token 记录不猜测审查次数。首次启用会先备份 SQLite 再重算 Codex 历史价格，原始 token、Cursor 费用不变。Fork 使用首条 session_meta 确定所有者，继承的旧历史不会再次计费。

额度展示按本周期已记录的美元消耗计算：已用百分比 = 累计美元 / 套餐额度 × 100，剩余额度 = max(0, 套餐额度 − 累计美元)。金额及百分比显示两位小数，内部累计保留原精度。Codex 每周 Plus $100、Pro5x $500、Pro20x $2000；Cursor 一方模型每月 Pro $450、Pro+ $1200、Ultra $3000。Codex 历史月度汇总也使用记录成本。上述为用户设定的展示口径，不是服务端账单；缺失或未计价记录可能少算。服务端原始百分比单独保留给历史额度图和验证采样。Cursor 三方模型池及 Codex 5小时窗口不套用这组容量。

### 独立查询与实验记录

总览底部的“Codex 额度验证”提供查询一次、开始记录、结束记录和导出记录。它通过本机 Codex app-server 的 account/rateLimits/read 使用现有登录态，仅查询额度，不发起模型任务。每条查询保留请求起止时间、窗口/套餐/重置时间、整数百分比、失败状态和计价版本，不保存凭证、完整响应体或对话内容。

挂件启动后默认约每15秒主动查询 Codex 额度，无需开始实验；隐藏窗口也继续。“开始/结束记录”用于标记实验区间，结束实验不会停止后台查询。按查询开始时间安排间隔，请求不重叠；请求超时、电脑休眠或退出挂件期间会出现时间缺口，恢复后不补发积压请求。每次保留查询起止时间、成功/失败、触发来源与上次成功响应时间。15秒是目标采样间隔，并不保证服务端真实扣费时间误差小于15秒。结束记录时再查询一次；失败会保留失败状态，不伪造终点余额。近期成功主动查询优先用于展示，超过两分钟则退回明确标注的会话快照。

验证数据在 `%APPDATA%/cursor-usage-widget/codex-verification.jsonl`，状态在同目录 `codex-verification-state.json`。导出当前或最近一次实验的 JSON，包含独立额度查询、模型/token/成本明细、Fast未知数量、审批次数、失败查询和百分比变化；用量额外保留起止各120秒，以便重新调整边界。原始回退不做单调截断。输出版本号固定，可追溯假设；不会把这些新查询混入历史会话快照数据库。

推荐单一模型、Fast关闭、人工审批，开始/结束时等已有任务完成。多积累几个百分点后分析；整数取整、服务端结算延迟、其他设备消耗仍可能影响结果，采样不能获得小数精度后台余额。
